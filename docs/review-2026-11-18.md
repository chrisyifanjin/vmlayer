# Response to the first external review (commit a292eb7)

Two reviewers read vmlayer at commit `a292eb7`: an architecture review and
a correctness audit. This page records what we concluded about each
finding, what we changed, and where. Status is updated as work lands.

## Architecture

| # | Finding | Verdict | Action | Status |
|---|---|---|---|---|
| A1 | The daemon is in the data path of running VMs (NBD, memory fill, DNS proxy, lease renewal), yet VMs are meant to survive a daemon stop. | **Agree.** This is the root cause of several Tier 0 items. | A small helper process per VM (`vmlayer-shim`, after containerd's shim v2) owns the VM's data-path services and its fencing deadline and dies with the VM; the daemon only gives orders. | done (decision 0019) |
| A2 | One lease per sandbox, judged by wall clock: about 100 object-store writes per second at 1,000 sandboxes, and safety depends on clocks. | **Agree.** | One lease per host (like Kubernetes node leases) plus an ownership record with an epoch per sandbox; writes scale with hosts and a stale owner cannot overwrite a newer one. | done (decision 0014 update) |
| A3 | Placement and policy live in the client SDK; every language must copy them and nothing can refuse a full host. | **Agree.** | Any daemon answers "place this sandbox"; the target daemon admits or refuses. SDKs only follow the answer. | done (`PlaceSandbox`, admission control, SDK `Cluster` in Python and TypeScript) |
| A4 | The fast paths (boot templates, memory-snapshot create) exclude sandboxes with a workspace volume, which real agent sessions always have. | **Agree.** The suggested placeholder drive works with Firecracker's post-boot drive update. | Templates carry an empty placeholder drive; on restore the real volume replaces it and the guest mounts it. | done: create with a workspace 1.30 s cold, 0.20-0.30 s from a template (nested KVM) |
| A5 | One trusted caller per daemon is acceptable but must be stated, and needs mutual TLS. | **Agree.** | TLS and mutual TLS on TCP listeners, and the trust model stated in the docs. | done (decision 0020) |

## Tier 0: paths that lose data or run a sandbox twice

| # | Finding | Verdict | Action | Status |
|---|---|---|---|---|
| T0.1 | Sandbox restore attaches a partly downloaded (lazy) volume image directly; the guest reads zeros. | **Confirmed** (`manager.rs` restore path skips `prepare`). | Restore and fork prepare every volume like create does. | done |
| T0.2 | A failed manifest fetch at daemon start only logs a warning; the half-downloaded image is then used as complete. | **Confirmed** (`volumes.rs` `resume_lazy`). | An incomplete volume is refused until its download can resume; resumption is retried. | done |
| T0.3 | Garbage collection can delete a chunk that a running upload just renewed. | **Confirmed**: GC judges age from a listing taken before the renewal. | GC re-checks a chunk's age right before deleting it, and an upload verifies every chunk it reused after writing its manifest, re-uploading any that vanished. | done |
| T0.4 | Lease renewal has no time-out, and fencing stops when the daemon stops. | **Confirmed.** | Renewals are bounded; the fencing deadline moves into the per-VM shim (A1), which kills the VM when it is not extended in time. | done (decision 0019) |
| T0.5 | Crash paths have no tests; multi-host tests use one machine and a `file://` store. | **Agree.** | Crash tests (daemon killed during lazy restore, during lease renewal, host loss) and cluster tests against S3 (MinIO) with conditional writes. Only `file://` may fall back to delete-then-create; any other store without conditional writes now fails loudly. | done: crash tests on KVM in CI; cluster, lease, ownership and rescue tests run against MinIO and Azurite in CI |

## Tier 1: safe to expose

| # | Finding | Verdict | Action | Status |
|---|---|---|---|---|
| T1.1 | One shared token, no TLS, no per-caller permissions. | **Agree.** | TLS and mutual TLS; tokens with a tenant and a role (read, write, admin); tenants see only their own sandboxes, volumes and snapshots, and other tenants' IDs answer "not found". | done (decision 0020; `tests/test_auth.py` runs a mutual-TLS daemon with two tenants) |
| T1.2 | Any absolute host path is accepted as an image. | **Confirmed**: a caller could boot any host file as a disk. | Host paths only from `[firecracker] image_dirs`, checked after resolving symlinks and `..`; empty by default. | done |
| T1.3 | Network gaps on the Docker backend. | **Agree.** | Block cloud metadata in each sandbox's own network namespace (blackhole routes added by a short-lived `NET_ADMIN` helper before the sandbox's code runs; the sandbox cannot remove them). This works on any engine, including Docker Desktop, where host firewall rules would not reach. State plainly what the Docker backend does not isolate. | done (usage.md, "What the Docker backend does not isolate") |

## Tier 2: fit the agent runtimes

| # | Finding | Verdict | Action | Status |
|---|---|---|---|---|
| T2.1 | Upload/download and an asyncio client. | **Agree** on the asyncio client. Both SDKs already copied files and directory trees in and out (`files.upload`, `files.download`) at the reviewed commit. | Native `grpc.aio` Python client (`vmlayer.aio`) with sandboxes, commands, processes, files, snapshots and ports; it shares request building with the sync SDK. | done (`tests/test_aio.py`) |
| T2.2 | A Harbor adapter reaches many agents through one class. | **Agree.** | Harbor environment adapter, loaded by import path; exec gained a `user` field (Harbor runs agents as task users) on both backends. | done (`tests/test_harbor.py` runs trials with Harbor's CLI in CI; also run on Firecracker) |
| T2.3 | An authenticated HTTPS expose, for agents that run whole inside the sandbox. | **Agree.** | Exposed ports reachable through the daemon over HTTPS with a per-port token. | planned |
| T2.4 | A credential proxy on the egress path, so the sandbox never holds real keys. | **Agree**; the strongest request. | Egress proxy that injects configured credentials for allowed hosts; the guest only sees placeholders. | planned |
